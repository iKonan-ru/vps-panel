# Файлы выкладки

Панель ставится и обновляется только из релизов: установка, переменные, обновление,
резервная копия - [docs/install.md](../docs/install.md). Здесь - что лежит в `deploy/` и как
из этого получается релиз.

| Файл | Что это |
| --- | --- |
| `Dockerfile` | образ панели: сервер, интерфейс, xray для маршрута до Telegram, агент и сборки naive и wdtt из стадии `artifacts` |
| `Dockerfile.caddy`, `Caddyfile` | образ Caddy: HTTPS панели, имени подписок и поддоменов панелей сервисов; Caddyfile подключает и свои сайты из `sites/` (`/opt/vps-panel/sites/*.caddy`) |
| `fail2ban-panel.conf` | фильтр fail2ban для неудачных входов в панель по журналу Caddy |
| `release/vps-panel` | команда на сервере панели: установка, обновление, откат, домен, восстановление, удаление |
| `release/compose.yml` | контейнеры panel и caddy релизной установки |
| `release/fail2ban-panel.jail` | jail fail2ban входа в панель (путь к журналу подставляет `vps-panel install`) |

Релиз собирает `.github/workflows/release.yml` по тегу `vX.Y.Z` или `vX.Y.Z-beta.N`
(`tools/release.sh`): агент, Caddy с forwardproxy (`tools/build-naive.sh`) и wdtt-server
(`tools/build-wdtt.sh`) кладутся в образ панели, образы панели и Caddy (amd64 и arm64) - в
ghcr.io, файлы из `release/`, `Caddyfile`, `fail2ban-panel.conf`, `install.sh` и бинарники
агента - в релиз на GitHub.

## Caddy

Панель - на домене панели (`PANEL_DOMAIN`), подписки и личные страницы - на имени подписок
(`SUB_DOMAIN`), панели сервисов - на поддоменах `*.<домен панели>`; без домена панель
работает по IP с сертификатом Let's Encrypt на IP. На имени подписок Caddy отдаёт только
`/sub/*` и `/c/*`, на имени панели они, наоборот, закрыты. Журналы - `access.log` и
`access-sub.log` в томе Caddy, токены из адресов в них не пишутся. Пока панель перезапускается,
Caddy держит запросы до 30 с (`lb_try_duration`), а не отдаёт 502.

Контейнеры урезаны: `cap_drop: [ALL]`, `no-new-privileges`, корень только для чтения; panel
пишет только в `/data` и `/tmp`, caddy - в свои тома и `/tmp`, из привилегий у него только
порты 80 и 443.

## Маршрут до Telegram

С сервера панели в России api.telegram.org недоступен. В образе панели - xray; панель
запускает его дочерним процессом (HTTP-прокси 127.0.0.1:3128 внутри контейнера) с выходами
через VLESS Reality своих серверов с 3X-UI: основной выбирается в "Настройках", запасные
панель готовит сама на отмеченных там серверах (по умолчанию - на всех). Через него же идут запросы к GitHub и ghcr.io, если напрямую они не
проходят. `TG_PROXY_URL` - необязательный внешний прокси на случай, когда xray не запущен.

## Файлы для команд

Панель раздаёт по `/files/<путь>` (без входа, контрольная сумма - `/files/sha256/<путь>`)
сборки из образа: wdtt-server и Caddy с forwardproxy для прокси для браузера. Расширение
Firefox панель подписывает сама ключом API addons.mozilla.org из "Настроек" и хранит в
`data/firefox`.
