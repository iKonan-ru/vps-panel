# Установка и обслуживание

## Требования

**Сервер панели**

- Linux с systemd, root (проверено на Ubuntu 24.04); docker с compose plugin установщик
  поставит сам (get.docker.com).
- 1 ГБ памяти и больше, около 3 ГБ на диске под образы.
- Открытые 80/tcp, 443/tcp и 443/udp; порты 80 и 443 не заняты.
- Домен - по желанию (без него - см. "Панель без домена"). С доменом - A-записи на сервер
  панели:
  - имя панели, например `panel.example.com`;
  - имя подписок и личных страниц клиентов, например `sub.example.com` (по желанию: без
    него они живут на имени панели);
  - `*.example.com` - для входа в панели 3X-UI и MTProxyL через панель
    (`<сервер>-xui.example.com`).
- Доступ к GitHub и ghcr.io с сервера (установка и обновления).

**Управляемые серверы**

- Linux x86_64 или arm64 с systemd, root.
- Исходящий HTTPS до панели. Входящий SSH нужен только для установки агента из панели;
  можно и без него - выполнить команду установки на сервере вручную.

Сервер панели может быть и обычным сервером: агент, VPN-сервисы и прокси для браузера на
нём работают так же (сертификат прокси для браузера тогда выпускает Caddy панели).

## Установка

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/iKonan-ru/vps-panel/main/install.sh)
```

| Ключ | Что делает |
| --- | --- |
| `--beta` | канал "бета": ставится последний пре-релиз, потом приходят и пре-релизы |
| `--version X.Y.Z` | конкретная версия |
| `-y` | без вопросов: `PANEL_DOMAIN` (пусто - панель по IP), `ACME_EMAIL`, `SUB_DOMAIN`, `PANEL_LOGIN` (пусто - случайный) из окружения |

Установщик:

1. ставит команду `vps-panel` (`/usr/local/bin/vps-panel`) из выбранного релиза;
2. спрашивает домен панели (Enter - без домена, по IP), имя подписок, почту для Let's Encrypt
   и логин администратора (Enter - случайный, вида `admin-k7m2qa`);
3. проверяет DNS (имена указывают на этот сервер, есть ли `*.домен`) и свободные порты;
4. ставит docker, если его нет;
5. пишет `/opt/vps-panel/.env` с новым `SESSION_SECRET`, скачивает `compose.yml`, `Caddyfile`
   и файлы fail2ban релиза (сверка с `release.sha256`), образы из ghcr.io;
6. создаёт администратора со случайным паролем (20 символов);
7. запускает панель и ждёт её ответа;
8. открывает 80 и 443 в ufw (если он включён), включает fail2ban для входа в панель и
   службу обновлений `vps-panel-update.path`;
9. печатает сводку для входа:

```
================================================================
 VPS Panel 1.0.0-beta.12 установлена
================================================================
 Адрес:      https://panel.example.com
 Логин:      admin-k7m2qa
 Пароль:     Xq7mK2pRtV9bN4wLc8Hs
 2FA:        настраивается при первом входе (приложение-аутентификатор)
 Подписки:   https://sub.example.com
================================================================
 Сохраните пароль сейчас: он показан один раз, восстановления нет.
 Сброс пароля или 2FA - только здесь, в консоли: vps-panel admin password | 2fa
================================================================
```

Пароль больше нигде не хранится в открытом виде. Мастера в браузере нет: до установки
администратора панель никого не пускает.

Сертификаты Let's Encrypt Caddy получает сам при первом запросе к имени (или к IP).

## Первые шаги

1. Вход с логином и паролем из сводки. При первом входе панель показывает QR-код для
   приложения-аутентификатора (Google Authenticator, Aegis, 1Password) и 8 резервных кодов:
   без 2FA в панель не попасть. Пароль можно сменить в разделе "Аккаунт" (нажать на своё
   имя в меню).
2. "Настройки" - "Бэкап панели": пароль бэкапа (храните отдельно от сервера), отправка в
   Telegram раз в сутки.
3. "Настройки" - "Уведомления в Telegram": бот, chat id, какие события присылать. Если сервер
   панели в России, там же - "Маршрут до Telegram" через свои заграничные серверы.
4. "Серверы" - "Добавить сервер".

## Администратор: пароль и 2FA

Администратор один. В панели, раздел "Аккаунт": смена логина и пароля (с текущим паролем;
другие устройства при смене пароля выходят), перенастройка 2FA (новый телефон), новые
резервные коды, активные сессии с закрытием по одной, попытки входа.

Восстановления пароля по почте или через интерфейс нет. Забыли пароль или потеряли телефон с
2FA и резервные коды - сброс только в консоли сервера панели (root):

| Команда | Что делает |
| --- | --- |
| `vps-panel admin` | логин, включена ли 2FA, сколько открытых сессий |
| `vps-panel admin password` | новый случайный пароль (печатается); все сессии закрываются |
| `vps-panel admin 2fa` | сбросить 2FA: при следующем входе - новый QR-код; все сессии закрываются |
| `vps-panel admin login <имя>` | сменить логин |
| `vps-panel admin init [имя]` | создать администратора, если установка прервалась до этого |

## Панель без домена

Если при установке не указать домен, панель работает по адресу `https://<IP сервера>`:

- сертификат - Let's Encrypt на IP-адрес (профиль shortlived, 6 дней; Caddy продлевает сам,
  браузер и агенты ему доверяют); нужен внешний IPv4 и свободные 80 и 443;
- подписки и личные страницы клиентов - на том же адресе (`https://<IP>/sub/...`);
- агенты, сервисы, клиенты, Telegram, бэкап - всё как с доменом.

Без домена не работает то, что держится на именах:

- вход в панели 3X-UI и MTProxyL через панель (поддомены `<сервер>-xui.<домен>`): их
  открывают напрямую по адресу сервера, если порт панели сервиса открыт, или через
  SSH-туннель;
- имя прокси для браузера (naive) на сервере панели по умолчанию - его вводят сами (своё имя
  под A-записью на этот сервер);
- отдельное имя для подписок.

Домен можно добавить позже:

```bash
vps-panel domain panel.example.com            # --sub sub.example.com - и имя для подписок
```

Команда проверяет A-запись, переводит панель на домен и перезапускает её. Прежний адрес по IP
продолжает работать (`PANEL_ALIAS` в `.env`): по нему ходят агенты и подписки, выданные
раньше. Агенты сами переходят на новый адрес при следующем подключении. Так же меняется и
один домен на другой.

## Раскладка на сервере

| Путь | Что там |
| --- | --- |
| `/opt/vps-panel/compose.yml` | контейнеры панели и Caddy; заменяется при обновлении - свои правки держите в `compose.override.yml` рядом |
| `/opt/vps-panel/Caddyfile` | конфиг Caddy; заменяется при обновлении |
| `/opt/vps-panel/.env` | настройки установки (ниже) |
| `/opt/vps-panel/data` | база SQLite, ключи панели, конфиг xray, подписанное расширение Firefox, ход обновлений |
| том `vps-panel_caddy_data` | сертификаты Caddy и журналы доступа |
| `/usr/local/bin/vps-panel` | команда обслуживания |

## Переменные (.env)

| Переменная | Обязательна | Что это |
| --- | --- | --- |
| `PANEL_DOMAIN` | да | домен панели (A-запись на этот сервер) или IP - панель без домена |
| `PANEL_TLS` | нет | `domain` - сертификаты на имена; `ip` - и на IP-адрес (панель без домена или прежний адрес по IP) |
| `PANEL_SNI` | нет | IP-адрес панели при `PANEL_TLS=ip`: его сертификат отдаётся запросам без имени |
| `PANEL_ALIAS` | нет | прежний адрес панели после `vps-panel domain`; пусто - только `PANEL_DOMAIN` |
| `ACME_EMAIL` | да | почта для Let's Encrypt |
| `SESSION_SECRET` | да | секрет сессий и ключ шифрования данных в базе; потерять - значит потерять зашифрованное |
| `SUB_DOMAIN` | нет | имя для подписок и личных страниц; пусто - на имени панели |
| `PANEL_VERSION` | да | версия образов; меняет `vps-panel update` |
| `PANEL_CHANNEL` | нет | `stable` или `beta`: канал для `vps-panel update` без версии |
| `TG_PROXY_URL` | нет | внешний HTTP-прокси до api.telegram.org вместо встроенного xray |
| `LOG_LEVEL` | нет | `info` по умолчанию |

Остальное (Telegram, уведомления, бэкап, маршрут до Telegram, хеши звонков WDTT, документы
OpenFlux, расширение Firefox) настраивается в интерфейсе, раздел "Настройки". После правки
`.env` - `vps-panel restart`.

## Подключение сервера

1. "Серверы" - "Добавить сервер": имя, адрес, порт SSH, хостинг и оплата (по желанию).
2. Установка агента: панель заходит по SSH (пароль root или ключ панели) и ставит агента сама
   или показывает команду для ручного запуска на сервере.
3. Агент регистрируется одноразовым токеном, запоминает ключ панели и с этого момента работает
   только с ней.
4. Во вкладке "Обзор" - замечания аудита с кнопками исправления; сервисы ставятся из каталога
   команд, ключи root - во вкладке "Ключи".

Отпечаток ключа хоста SSH панель запоминает при первом подключении и сверяет потом; после
переустановки ОС сервера его сбрасывают в окне установки агента.

## Обновление

- **Панель.** Новые версии - релизы на GitHub: `vX.Y.Z` (стабильные) и `vX.Y.Z-beta.N`
  (пре-релизы, канал "бета"). Панель проверяет их раз в 6 часов; "Настройки" - "Версия
  панели" показывает новые версии со списком изменений. Кнопка "Обновить" или автообновление
  в заданный час (UTC); о новой версии - уведомление в Telegram. Ставит обновление служба на
  сервере: скачивает файлы релиза и образы, перезапускает панель и проверяет её ответ, при
  неудаче возвращает прежнюю версию. Из консоли - `vps-panel update [версия]`, откат -
  `vps-panel rollback`.
- **Агенты.** Бинарники агента лежат в образе панели. После обновления панели устаревшие агенты
  обновляются сами по одному серверу (первая ошибка останавливает раскатку; выключатель - в
  "Версии панели"); вручную - кнопкой в карточке сервера или всех сразу на странице серверов.
- **Сервисы на серверах.** Новые версии 3X-UI, Xray в нём и MTProxyL панель проверяет раз в
  6 часов, обновления пакетов приходят в снимках агента; обновить - в карточке сервера.

## Удаление

| Команда | Что снимается | Что остаётся |
| --- | --- | --- |
| `vps-panel uninstall` | контейнеры и образы панели, служба обновлений, jail fail2ban панели | данные в `/opt/vps-panel`, сертификаты, команда `vps-panel` |
| `vps-panel uninstall --purge` | то же и данные, сертификаты, команда `vps-panel` | агент, прокси для браузера, VPN-сервисы этого сервера |
| `vps-panel uninstall --full` | всё, что ставила панель на этом сервере: панель с данными, агент, прокси для браузера, port-sync, VPN-сервисы (3X-UI, MTProxyL, WDTT, OpenFlux, контейнеры Amnezia - список подтверждается отдельно), docker - если его ставил установщик и других контейнеров нет | защита сервера: вход SSH по ключу, jail sshd, автообновления безопасности, ufw и его правила |

`--full` спрашивает домен панели для подтверждения (`-y` - без вопросов). Агенты на других
серверах снимаются там же - см. [apps/agent/README.md](../apps/agent/README.md).

## Бэкап и восстановление

"Настройки" - "Бэкап панели": пароль бэкапа, отправка в Telegram раз в сутки, кнопки
"Отправить сейчас" и "Скачать". В архиве - снимок базы, `SESSION_SECRET`, ключ SSH панели,
ключ панели для агентов и конфиг xray.

Восстановление на новом сервере - после установки панели (тем же или другим адресом), одной
командой: она расшифрует архив (спросит пароль бэкапа), остановит панель, разложит базу и ключи,
подставит `SESSION_SECRET` в `.env`, запустит панель и проверит её ответ. Прежние данные этой
установки остаются в `/opt/vps-panel/data/before-restore-<время>`.

```bash
vps-panel restore vps-panel-backup-<дата>.tar.gz.enc        # -y - без вопроса; пароль - BACKUP_PASSWORD
```

После восстановления вход - прежним логином, паролем и 2FA; агенты подключаются сами. Сервер,
агента которого переставляли уже после этого бэкапа, будет "не в сети" (токен агента новее
базы): переустановить агента в его карточке. Ключа SSH панели в бэкапе нет, если панель им ещё
не пользовалась: для установки агента ключом добавьте новый ключ панели на сервер.

Вручную (то же самое по шагам):

```bash
cd /root && openssl enc -d -aes-256-cbc -pbkdf2 -iter 100000 -in vps-panel-backup-<дата>.tar.gz.enc | tar xz
B=/root/vps-panel-backup
cd /opt/vps-panel && docker compose stop panel
cp $B/panel.db $B/panel_agent_ed25519.pem data/
cp $B/panel_ssh_ed25519* data/ 2>/dev/null || true    # есть, если панель уже входила по ключу
mkdir -p data/xray && cp $B/xray/config.json data/xray/
rm -f data/panel.db-wal data/panel.db-shm && chown -R 1000:1000 data && chmod 600 data/panel_agent_ed25519.pem
grep -v '^SESSION_SECRET=' .env > .env.new && grep '^SESSION_SECRET=' $B/panel.env >> .env.new && mv .env.new .env && chmod 600 .env
docker compose up -d
```

Без ключа панели для агентов (`panel_agent_ed25519.pem`) восстановленной панели не поверит ни
один агент; без `SESSION_SECRET` не прочитать зашифрованное в базе.

## Переезд со сборки из исходников

Панель, поставленная через `git clone` и `deploy/install.sh`, переезжает на релизы одной
командой - с теми же данными и сертификатами (тома Caddy остаются прежние):

```bash
curl -fsSL https://github.com/iKonan-ru/vps-panel/releases/latest/download/vps-panel -o /usr/local/bin/vps-panel
chmod 755 /usr/local/bin/vps-panel
vps-panel migrate              # --beta - канал с пре-релизами
```

Образы скачиваются до остановки старой панели, перерыв - только перезапуск; если новая не
поднялась, всё возвращается назад. Старые файлы в `/opt/vps-panel/deploy` после проверки можно
удалить.

## Работа из России

- Docker Hub с серверов в России бывает недоступен: образы панели и Caddy лежат в ghcr.io.
- api.telegram.org с российского сервера недоступен: уведомления и бэкап идут через xray-клиент
  панели к своим серверам с 3X-UI за границей ("Маршрут до Telegram"), запасные выходы панель
  готовит сама; не доходит - сообщения копятся и уходят после восстановления.
- Доступность серверов из российских домашних сетей панель проверяет зондами Globalping.
