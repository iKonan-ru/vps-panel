# Как устроено

```
   администратор                     клиенты: подписка, личная страница, расширение
        |  HTTPS                                  |  HTTPS
        v                                         v
  +--------------------------- сервер панели (docker) ---------------------------+
  |  caddy:  <домен> - панель, <SUB_DOMAIN> - /sub и /c, *.<домен> - панели      |
  |          сервисов; сертификаты Let's Encrypt, HTTP/3                         |
  |  panel:  Fastify + SQLite, интерфейс React, xray для выхода в Telegram       |
  +------------------------------------------------------------------------------+
        ^   wss://<домен>/ws/agent?v=2 - агент подключается сам
        |   (X25519 + подпись ключом панели ed25519, затем AES-256-GCM)
  +-----+-----------+   +-----------------+   +-----------------+
  |  vps-agent      |   |  vps-agent      |   |  vps-agent      |
  |  3X-UI, MTProxyL|   |  AWG, WDTT, ... |   |  ...            |
  +-----------------+   +-----------------+   +-----------------+
```

- **Поставка**: GitHub Actions на тег версии собирает образы `ghcr.io/ikonan-ru/vps-panel`
  (панель, интерфейс, агент, сборки naive и wdtt, xray) и `vps-panel-caddy` для amd64 и
  arm64 и публикует релиз; установщик и команда `vps-panel` берут файлы и образы оттуда.
- **Панель** (`apps/server`, `apps/web`): Fastify 5, better-sqlite3 с Drizzle, React 19,
  Vite, Tailwind 4, TanStack Router и Query. Живые обновления интерфейса - по `/ws/ui`.
- **Протокол** (`packages/protocol`): zod-схемы сообщений агент-панель и типы API, общие для
  сервера и интерфейса; Go-зеркало - в `apps/agent/internal/proto`.
- **Агент** (`apps/agent`): один статический бинарник на Go (linux amd64 и arm64) и
  systemd-юнит. Снимок сервера раз в 5 минут и сразу при падении или подъёме сервиса,
  метрики, операции из белого списка, терминал, туннель к панелям сервисов на 127.0.0.1,
  проверки доступности из России (Globalping), самообновление с проверкой контрольной суммы.
- **Расширение** (`apps/extension`): чистый JS без сборки, один код для Chrome (MV3, архив с
  личной страницы) и Firefox (MV2, подписанный архив, автообновление).

## Безопасность

- Вход: пароль (argon2) и обязательный TOTP, резервные коды, пауза после неудачных попыток,
  fail2ban по логу Caddy; cookie сессии с префиксом `__Host-`. Сессия живёт 72 часа без
  запросов и 30 дней абсолютно; активность обновляется в `last_seen_at`. Администратора
  создаёт установка в консоли (случайный пароль), мастера в браузере нет - панель до этого
  никого не пускает; 2FA настраивается при первом входе. Восстановления пароля нет: сброс -
  только root в консоли сервера панели (`vps-panel admin`).
- Особо чувствительные действия (бэкап панели, управление ботом) требуют step-up: пароль и
  2FA, подтверждение действует 5 минут.
- Без домена панель работает по `https://<IP>` с сертификатом Let's Encrypt на IP-адрес;
  смена адреса (`vps-panel domain`) безопасна для агентов: они верят ключу панели, а не адресу.
- Канал агента v3: агент верит ключу панели ed25519, а не домену и сертификату. После
  проверки ключа панели и установки AES-256-GCM-канала агент передаёт токен только внутри
  этого канала, а панель хранит лишь его хеш. Сервер, один раз подключившийся по v3, больше
  не принимает v2; `AGENT_V2_COMPAT=0` отключает v2 глобально.
- Агент выполняет только операции из белого списка с проверкой аргументов, команды
  собираются без оболочки.
- Пароли панелей, ключи клиентов AWG, токены 3X-UI и TOTP-секреты в базе зашифрованы
  AES-256-GCM ключом из `SESSION_SECRET`; резервные коды - HMAC с pepper.
- Бэкап панели - v2 (AES-256-GCM, PBKDF2 600k), копии серверов - потоковый v3; старые v1
  читаются, но новые не создаются.
- Ограничены размер WS-сообщений, очередь рукопожатия, частота `/api/proxy/ask`, число
  терминалов и очередь туннеля; медленные UI-клиенты отключаются по `bufferedAmount`.
- Секреты не пишутся в журнал действий, в значения по умолчанию команд и в вывод.
- Контейнеры урезаны: корень только для чтения, `cap_drop: ALL`, `no-new-privileges`;
  CSP, панель закрыта от поисковиков. Прав на docker у контейнера панели нет: обновления
  ставит служба на сервере панели по запросу из панели (только версия вида X.Y.Z и только образы
  проекта).
- Панели сервисов на серверах слушают только 127.0.0.1, вход в них - через панель.
- Изменения на серверах - только явными действиями с подтверждением, по одному серверу.
- При настроенном отдельном `SUB_DOMAIN` личные страницы и подписки на origin панели не отдаются.
