# Изменения

Версии - [semver](https://semver.org/lang/ru/): X.Y.Z - стабильный релиз, X.Y.Z-beta.N -
пре-релиз (канал "бета"). Текст раздела версии становится описанием релиза на GitHub.

## 1.0.0-beta.12 - 12.10.2026

- 3X-UI 3.10: его установщик печатает пароль и токен API открытым текстом - токен сохранялся в
  журнале панели (и попадал в бэкапы), пароль был виден в живом выводе. Вывод установщика теперь
  маскируется, токен API вычищается из журнала любых команд, пароли из формы не уходят даже в
  живой вывод; файл итога установщика с паролем и токеном (/etc/x-ui/install-result.env)
  удаляется.
- port-sync переставал следить за базой 3X-UI: пока 3X-UI ставится, база меняется десятки раз
  подряд, служба упиралась в лимит запусков, и systemd выключал слежение до перезагрузки (порты
  новых inbound-ов открывались только таймером, до 2 минут). Лимит снят; агент при запуске
  обновляет юниты port-sync и поднимает выключенное слежение.
- Обновление пакетов, установка пакетов эталона и сервисов ждут, пока apt занят другим процессом
  (до 10 минут), а не падают: сразу после включения автообновлений система сама запускает apt.
  После неудачного обновления кнопка "Обновить" снова доступна (раньше - только после "Скрыть").
- Переустановка агента на сервере с переустановленной ОС: вместо "SSH: Host denied (verification
  failed)" - понятная ошибка о смене ключа хоста (с подсказкой "Сбросить отпечаток SSH" и
  предупреждением, если сервер не переустанавливали).
- После переустановки 3X-UI (или его обновления) не висит устаревшее "доступно обновление Xray"
  на уже установленную версию: строка скрывается до перепроверки, перепроверка запускается сама.
- Доступность из России: цели inbound-ов снятого 3X-UI убираются через 3 минуты, а не после
  следующей проверки (до 30 минут).
- "Установить сервис" в карточке сервера открывает каталог, а форма команды - сразу с этим
  сервером.
- Исчерпанный лимит запросов GitHub (60 в час без токена) - понятным текстом со временем сброса,
  а не "GitHub: 403".

- Прокси для браузера на сервере панели: в конце установки - подсказка, что клиенты заводятся
  на сервере панели только после его включения в "Серверах клиентов".
- WDTT: его установщик копировал в iptables разрешения для всех портов, открытых на тот
  момент, и ставил их выше ufw - порт удалённого сервиса оставался открытым (и после удаления
  самого WDTT). Где порты ведут ufw и port-sync (после "Привести к эталону"), панель убирает
  эти правила сразу после установки и при удалении WDTT, порты WDTT открывает port-sync.
- Установка с `--beta`: "Версия панели" сразу на канале "бета" (канал установки), раньше там
  стоял "стабильный" и новые беты не показывались, пока не переключить руками.
- Привязки клиентов к сервису, снятому с сервера руками (не командой панели), убираются через
  30 минут его отсутствия и тогда, когда панель за это время перезапускалась: отсчёт хранится в
  базе (раньше каждый перезапуск его обнулял, и привязка висела "работает").

## 1.0.0-beta.11 - 12.10.2026

- Панель без домена: `https://<IP>` не открывалась ни в браузере, ни у агентов (рукопожатие
  TLS рвалось). Запрос без имени Caddy вёл по правилу сертификатов "по требованию", а панель
  отказывала в нём для своего IP; теперь разрешает - Caddy берёт уже выпущенный сертификат.
- Новая команда `vps-panel restore <файл>`: восстановление панели из бэкапа одной командой
  (спросит пароль бэкапа, прежние данные установки сохраняются). Инструкция по шагам в
  документации и README внутри бэкапа исправлена: команды ссылались на неверные пути, а
  копирование ключа SSH панели падало, если его нет в архиве.
- Удаление WDTT и экземпляра AWG сразу убирает привязки клиентов к ним (как у остальных
  сервисов), у AWG - только к удаляемому контейнеру; после удаления WDTT не остаются правила
  iptables, открывающие его порты.
- Маршрут до Telegram: после его настройки сообщения снова идут через xray, а не ещё час через
  агента на сервере (запасной путь запоминается на 10 минут).
- `vps-panel uninstall --full` закрывает в ufw порты снятых сервисов (оставался порт прокси для
  браузера).
- Установка с `--beta` ставит самую новую бету, а не первую в списке GitHub (он сортирует
  теги строкой: beta.10 у него раньше beta.2); панель и `vps-panel update` смотрят 100
  последних релизов вместо 30 и 50.

## 1.0.0-beta.10 - 12.10.2026

- Исправлено: в 1.0.0-beta.8 и beta.9 агенты новой версии отключались от панели по кругу -
  панель отправляла им сверку адреса до приветствия, агент считал это нарушением и рвал связь.
  Событие "агент на связи" теперь наступает только после приветствия, сверка адреса - через

## 1.0.0-beta.9 - 12.10.2026 (отозвана)

Релиз удалён: агенты новой версии отключались от панели (исправлено в 1.0.0-beta.10, она включает и изменения ниже).


- Установка без вопросов (`-y`) без домена: панель стартовала без адреса - пустой
  `PANEL_DOMAIN` из окружения перекрывал `.env`; теперь команда `vps-panel` берёт значения
  только из `.env`.
- Если установка обрывается после создания администратора, сводка с логином и паролем всё
  равно печатается.
- `vps-panel admin ... -y` - без вопроса; подписи в сводке выровнены.
- Заголовок CSP без пустого `wss://`.

## 1.0.0-beta.8 - 12.10.2026 (отозвана)

Релиз удалён по той же причине; изменения вошли в 1.0.0-beta.10.


- Администратор создаётся при установке: логин спрашивается (Enter - случайный), пароль
  всегда случайный; в конце установки - сводка для входа (адрес, логин, пароль), как у других
  панелей. Мастера в браузере больше нет - до установки администратора панель никого не
  пускает.
- 2FA по-прежнему обязательна и настраивается при первом входе (QR и резервные коды).
- Раздел "Аккаунт" (нажать на своё имя в меню): смена логина и пароля, перенастройка 2FA на
  новый телефон, новые резервные коды, активные сессии с закрытием по одной, попытки входа.
  Блок безопасности входа переехал сюда из "Настроек".
- Восстановления пароля нет: сброс из консоли сервера панели - `vps-panel admin password`,
  `vps-panel admin 2fa` (и `vps-panel admin` - логин, 2FA, сессии).
- Панель без домена: если при установке не указать домен, она работает на `https://<IP>` с
  сертификатом Let's Encrypt на IP-адрес (Caddy продлевает сам). Домен добавляется позже -
  `vps-panel domain <имя>`; прежний адрес продолжает работать, агенты новой версии сами
  переходят на новый.
- "Настройки" - "Версия панели": ссылка на панель на GitHub.
- README: раздел возможностей и скриншоты.
- Окно подробностей доступности из России: подсказка о "худшей из двух проверок" - только у
  MTProxyL.
