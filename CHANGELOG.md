# Изменения

Версии - [semver](https://semver.org/lang/ru/): X.Y.Z - стабильный релиз, X.Y.Z-beta.N -
предварительная версия (предварительный канал, beta). Текст раздела версии становится описанием релиза на GitHub.

## 1.0.0 - не выпущена

Первый стабильный релиз: тот же код, что 1.0.0-beta.18, проверенный на чистых серверах
(установка с доменом и без, переустановка ОС сервера, обновления и откаты, восстановление из
резервной копии). Установка - одной командой (README, раздел
"Установка"); стабильный канал - по умолчанию.

Что внутри:

- Серверы: список VPS с состоянием, нагрузкой, хостингом и оплатой; карточка сервера с
  метриками, firewall (ufw и port-sync), docker, сертификатами, резервными копиями,
  веб-терминалом и журналом. Агент подключается к панели сам по шифрованному каналу.
- Сервисы: 3X-UI (VLESS Reality и XHTTP), MTProxyL, AmneziaWG 2.0 и 3.x, WDTT, OpenFlux и прокси
  для браузера (NaiveProxy) - установка из каталога с проверкой перед запуском, обновления
  (блок "Версии" на вкладке сервиса), удаление с планом и подтверждением, вход в панели
  сервисов через панель без открытых портов.
- Клиенты: клиент заводится один раз - панель создаёт его во всех сервисах на нужных
  серверах и синхронизирует их с панелью; подписка для Happ, v2rayNG, Hiddify и личная
  страница с конфигами, QR и приложениями; живая статистика.
- Безопасность: аудит серверов с исправлением в один клик; вход в панель - пароль и
  обязательная 2FA, пауза после ошибок, fail2ban (свои серверы не банит); раздел "Аккаунт".
- Наблюдение: доступность из России через зонды Globalping с разбором по городам и сетям;
  уведомления в Telegram (с запасным путём через свои серверы) и ежедневная зашифрованная
  резервная копия панели.
- Обслуживание: обновление панели из интерфейса, кнопкой или автоматически в заданное время, с
  откатом при неудаче; агенты обновляются вслед за панелью; `vps-panel` в консоли -
  обновление, откат, восстановление из резервной копии, сброс пароля и 2FA.

Обновление с предварительных версий: панели на предварительном канале получат 1.0.0 обычным
обновлением. Чтобы дальше получать только стабильные версии: "Настройки" - "Версия панели" -
"Канал обновлений" - "стабильный" (или `vps-panel channel stable`). Изменения по шагам - в
разделах предварительных версий ниже.

## 1.0.0-beta.18 - не выпущена

- Адрес в ссылках MTProxyL следует за "Адресом для клиентов" сервера: задали имя - панель сама
  меняет адрес в ссылках MTProxyL и сразу синхронизирует клиентов сервера; убрали имя - в
  ссылках снова IP. Ход виден на странице сервера. Отдельная команда "MTProxyL: адрес в
  ссылках" и поле "Адрес в ссылках" при установке MTProxyL больше не нужны: установка берёт
  адрес для клиентов.
- Синхронизация клиентов, запущенная после открытия страницы сервера, сразу видна на ней
  (раньше - только после перезагрузки страницы).
- После завершения действия на сервере кнопки действий (в том числе в "Обслуживании")
  недоступны, пока панель не получит свежее состояние сервера: старое предупреждение больше не
  выглядит как неудачное обновление.
- Обновление агентов показывается полосой с ходом, как обновление панели: сервер, который
  обновляется сейчас, и итог.
- После обновления панели страница перезагружается сама; устаревший интерфейс в открытой
  вкладке тоже обновляется сам.
- Страница "Сервисы": без подсказки и счётчика "по эталону".

  сразу предлагает свободный порт (993, 8443, 2083 или 2087) - раньше это ловила только
  проверка перед запуском. 443 прокси для браузера по-прежнему уступает MTProxyL.
- `vps-panel help` показывает справку целиком.

## 1.0.0-beta.12 - 12.10.2026

- 3X-UI 3.10: его установщик печатает пароль и токен API открытым текстом - токен сохранялся в
  журнале панели (и попадал в бэкапы), пароль был виден в живом выводе. Вывод установщика теперь
  маскируется, токен API вычищается из журнала любых команд, пароли из формы не уходят даже в
  живой вывод; файл итога установщика с паролем и токеном (/etc/x-ui/install-result.env)
  удаляется.
- port-sync переставал следить за базой 3X-UI: пока 3X-UI ставится, база меняется десятки раз
  подряд, служба упиралась в лимит запусков, и systemd выключал слежение до перезагрузки (порты
  новых inbound-ов открывались только таймером, до 2 минут). Лимит снят; агент при запуске
  обновляет юниты port-sync и поднимает выключенное слежение.
- Обновление пакетов, установка пакетов эталона и сервисов ждут, пока apt занят другим процессом
  (до 10 минут), а не падают: сразу после включения автообновлений система сама запускает apt.
  После неудачного обновления кнопка "Обновить" снова доступна (раньше - только после "Скрыть").
- Переустановка агента на сервере с переустановленной ОС: вместо "SSH: Host denied (verification
  failed)" - понятная ошибка о смене ключа хоста (с подсказкой "Сбросить отпечаток SSH" и
  предупреждением, если сервер не переустанавливали).
- После переустановки 3X-UI (или его обновления) не висит устаревшее "доступно обновление Xray"
  на уже установленную версию: строка скрывается до перепроверки, перепроверка запускается сама.
- Доступность из России: цели inbound-ов снятого 3X-UI убираются через 3 минуты, а не после
  следующей проверки (до 30 минут).
- "Установить сервис" в карточке сервера открывает каталог, а форма команды - сразу с этим
  сервером.
- Исчерпанный лимит запросов GitHub (60 в час без токена) - понятным текстом со временем сброса,
  а не "GitHub: 403".

- Прокси для браузера на сервере панели: в конце установки - подсказка, что клиенты заводятся
  на сервере панели только после его включения в "Серверах клиентов".
- WDTT: его установщик копировал в iptables разрешения для всех портов, открытых на тот
  момент, и ставил их выше ufw - порт удалённого сервиса оставался открытым (и после удаления
  самого WDTT). Где порты ведут ufw и port-sync (после "Привести к эталону"), панель убирает
  эти правила сразу после установки и при удалении WDTT, порты WDTT открывает port-sync.
- Установка с `--beta`: "Версия панели" сразу на канале "бета" (канал установки), раньше там
  стоял "стабильный" и новые беты не показывались, пока не переключить руками.
- Привязки клиентов к сервису, снятому с сервера руками (не командой панели), убираются через
  30 минут его отсутствия и тогда, когда панель за это время перезапускалась: отсчёт хранится в
  базе (раньше каждый перезапуск его обнулял, и привязка висела "работает").

## 1.0.0-beta.11 - 12.10.2026

- Панель без домена: `https://<IP>` не открывалась ни в браузере, ни у агентов (рукопожатие

  отказывала в нём для своего IP; теперь разрешает - Caddy берёт уже выпущенный сертификат.

  документации и README внутри бэкапа исправлена: команды ссылались на неверные пути, а
  копирование ключа SSH панели падало, если его нет в архиве.
- Удаление WDTT и экземпляра AWG сразу убирает привязки клиентов к ним (как у остальных
  сервисов), у AWG - только к удаляемому контейнеру; после удаления WDTT не остаются правила
  iptables, открывающие его порты.
- Маршрут до Telegram: после его настройки сообщения снова идут через xray, а не ещё час через
  агента на сервере (запасной путь запоминается на 10 минут).
- `vps-panel uninstall --full` закрывает в ufw порты снятых сервисов (оставался порт прокси для
  браузера).
- Установка с `--beta` ставит самую новую бету, а не первую в списке GitHub (он сортирует
  теги строкой: beta.10 у него раньше beta.2); панель и `vps-panel update` смотрят 100
  последних релизов вместо 30 и 50.

## 1.0.0-beta.1 - 12.10.2026

Первый релиз: панель ставится одной командой из готовых образов и обновляется из себя.

- Проверка кода на GitHub (Actions) на каждый push и pull request.
- Версия панели в /api/health и в интерфейсе.
- Установка одной командой (install.sh) из готовых образов ghcr.io, команда vps-panel на
  сервере: обновление с откатом при неудаче, канал stable или beta, статус, логи, снятие.
- Настройки, "Версия панели": новые релизы в своём канале со списком изменений, кнопка
  "Обновить", автообновление в заданный час, уведомление в Telegram о новой версии.
- Агенты обновляются сами после обновления панели (выключатель в "Версии панели").
- Расширение Firefox подписывает сама панель ключом API addons.mozilla.org из Настроек: у
  каждой установки свой ID и адрес обновлений.
- Уведомления в Telegram по событиям (19 событий в группах), окно настройки, отключение
  серверов, задержка "сервер пропал", события "сервис упал/работает" и "сбой бэкапа".
- Прокси для браузера (naive) ставится и на сервер самой панели: сертификат выпускает Caddy
  панели.
- Удаление прокси для браузера, 3X-UI, MTProxyL и OpenFlux сразу убирает привязки клиентов.
- Исправлено: "MTProxyL: адрес в ссылках" брал IP вместо имени из "Адреса для клиентов".
