# Расширение браузера: прокси для браузера (Chrome и Firefox)

Выход в интернет через серверы VPS Panel только из браузера, без установки программ:
расширение настраивает браузер на HTTPS-прокси (Caddy с forwardproxy NaiveProxy на наших
серверах). Один код на оба браузера; MV3 для Chrome, MV2 для Firefox (манифест Firefox
собирает `tools/sign-firefox.mjs`). Чистый JS без сборки.

## Файлы

- `manifest.json` - манифест Chrome: разрешения (`proxy`, `webRequest`,
  `webRequestAuthProvider`, `storage`, `alarms`, `privacy`), `key` - постоянный ID
  `kbokmilkemjehecbicpkdfoedcjdpimo`; его `version` - версия расширения для обоих браузеров;
- `bg.js` - подписка `/sub/<токен>/browser`, маршрут и пароль к прокси, пинг серверов,
  проверка соединения, запрет утечки адреса через WebRTC, значок и проверка обновления, отчёт
  панели о себе (`/sub/<токен>/browser/status`: версия, браузер, включён ли прокси, сервер,
  ошибка в окне - при каждом изменении и раз в 15 минут; ни адресов страниц, ни трафика);
- `rules.js` - разбор своего списка "напрямую" (домены, `*.домен`, маски, IPv4 и IPv6, CIDR,
  страницы) и решение по адресу: в Chrome текст этих функций уходит в PAC, в Firefox они
  вызываются из `proxy.onRequest` (тесты сверяют ответы);
- `popup.html`, `popup.js` - окно: вкл/выкл, сервер с пингом или автовыбор, .ru, .рф и .su
  напрямую, свой список напрямую, ссылка, обновление;
- `icon*.png` - значки.

## Chrome

Панель отдаёт каталог архивом с личной страницы клиента (`/c/<токен>/chrome.zip`) и кладёт в
архив `config.json` со ссылкой подписки клиента - после установки ничего вводить не нужно.
Этот README в архив не попадает.

- Установка: скачать архив, распаковать, `chrome://extensions` - "Режим разработчика" -
  "Загрузить распакованное" - выбрать распакованную папку (не архив).
- Маршрут - PAC (`chrome.proxy`). Пароль - `webRequest.onAuthRequired`. Прокси с
  `probe_resistance` без пароля прикидывается сайтом и 407 не отвечает, поэтому расширение
  "прогревает" пароль запросом на секретное имя сервера.
- Обновление: панель отдаёт в подписке `extension.version` и ссылку на архив; у расширения
  версия старее - значок NEW и кнопки "Скачать" и "Перезапустить".

## Firefox

Обычный Firefox ставит только подписанные Mozilla расширения. `tools/sign-firefox.mjs`
собирает расширение, подписывает его на addons.mozilla.org (канал unlisted: в каталоге
не появляется) и кладёт в `deploy/files/firefox` архив `vps-panel-proxy-<версия>.xpi` и
`updates.json`; `tools/ship.sh` зовёт его сам, если задан `AMO_KEY_FILE`. ID расширения -
`vps-panel-proxy@<PANEL_DOMAIN>`, менять его нельзя.

- Установка: кнопка "Установить в Firefox" на личной странице (`/c/<токен>/firefox.xpi`).
  Подписанный архив один на всех, поэтому ссылку клиента расширение берёт с открытой личной
  страницы - только на имени `SUB_DOMAIN`, зашитом в сборку (`firefox.json`).
- Маршрут - `proxy.onRequest` на каждый запрос, пароль - заголовком `Proxy-Authorization`
  сразу в CONNECT, прогрев не нужен.
- Обновление - само: адрес `https://<SUB_DOMAIN>/sub/firefox/updates.json` зашит в
  манифест, Firefox проверяет его и ставит новую версию.

## Новая версия

Любая правка здесь - вместе с новой `version` в `manifest.json` (`tools/check.sh` без неё не
пропустит): по ней Chrome предлагает обновиться, а Mozilla подписывает новую версию Firefox
(одну версию дважды не подписывает). Закрытый ключ к `key` Chrome не нужен и не хранится:
расширение не упаковывается в .crx.
