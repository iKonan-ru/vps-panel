# Расширение Chrome: прокси для браузера

Выход в интернет через серверы VPS Panel только из Chrome, без установки программ:
расширение настраивает браузер на HTTPS-прокси (Caddy с forwardproxy NaiveProxy на наших
серверах).

MV3, чистый JS без сборки: этот каталог и есть расширение. Панель отдаёт его архивом с
личной страницы клиента (`/c/<токен>/chrome.zip`) и кладёт в архив `config.json` со ссылкой
подписки клиента - после установки ничего вводить не нужно. Без `config.json` ссылку
(личной страницы или подписки) вставляют в окне расширения. Этот README в архив не
попадает.

## Файлы

- `manifest.json` - разрешения (`proxy`, `webRequest`, `webRequestAuthProvider`, `storage`,
  `alarms`, `privacy`), `key` - постоянный ID `kbokmilkemjehecbicpkdfoedcjdpimo`;
- `bg.js` - подписка `/sub/<токен>/browser`, PAC (`chrome.proxy`), пароль к прокси
  (`webRequest.onAuthRequired`) и его прогрев (`probe_resistance`), пинг серверов,
  проверка соединения, запрет утечки адреса через WebRTC, значок и проверка обновления;
- `rules.js` - разбор своего списка "напрямую" (домены, `*.домен`, маски, IPv4 и IPv6, CIDR,
  страницы) в правила PAC;
- `popup.html`, `popup.js` - окно: вкл/выкл, сервер с пингом или автовыбор, .ru, .рф и .su
  напрямую, свой список напрямую, ссылка, обновление;
- `icon*.png` - значки.

## Установка у клиента

Скачать архив с личной страницы, распаковать, `chrome://extensions` - "Режим разработчика" -
"Загрузить распакованное" - выбрать распакованную папку (не архив).

## Обновление

Панель отдаёт в подписке `extension.version` из `manifest.json` и ссылку на архив; у
расширения версия старее - значок NEW и кнопки "Скачать" и "Перезапустить". Поэтому любая
правка здесь - вместе с новой `version` в `manifest.json` (`tools/check.sh` без неё не
пропустит). Закрытый ключ к `key` не нужен и не хранится: расширение не упаковывается в .crx.
