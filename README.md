# VPS Panel

Своя веб-панель для парка VPS с VPN-сервисами: серверы, сервисы и клиенты в одном месте,
подписки и личные страницы для людей, аудит безопасности, уведомления и бэкап в Telegram.

Панель ставится на один сервер в docker (Caddy + приложение), на каждый управляемый VPS -
небольшой агент на Go. Агент сам подключается к панели по шифрованному каналу, присылает
снимки и метрики и выполняет действия: открывать на серверах SSH-порты и API сервисов
наружу не нужно. Интерфейс на русском, работает и на телефоне (PWA).

## Возможности

### Серверы

- Список серверов: состояние агента, CPU, память, диск, хостинг, цена и дата оплаты,
  установленные сервисы, доступные обновления.
- Карточка сервера по вкладкам: обзор, firewall, docker, сертификаты, бэкапы, вкладки
  сервисов, веб-терминал, журнал действий сервера.
- Метрики раз в несколько секунд, пока открыта вкладка; нагрузка, сеть вход и выход.
- Firewall: правила ufw, port-sync (порты VPN открываются по тому, что реально слушает),
  фильтрация опубликованных портов docker через DOCKER-USER.
- Docker: контейнеры, их ресурсы, перезапуск и логи.
- Чистка диска (кэш docker и apt, старые логи, /tmp) с предварительным списком того, что
  будет удалено.
- Веб-терминал на сервере через агента, без открытого SSH; уход со вкладки или закрытие
  страницы сессию не обрывают - 3 минуты её можно подхватить с последним выводом.
- Обновление пакетов, перезагрузка, ключи root, бэкап конфигураций сервисов сервера.
- Обновление агентов кнопкой: по одному или всех по очереди.

### Аудит безопасности

Агент проверяет сервер при каждом снимке, панель показывает замечания с кнопкой
исправления там, где она есть:

- SSH: вход по паролю, PermitRootLogin, нет ключей у root;
- ufw не установлен или выключен, входящие не запрещены по умолчанию;
- порты контейнеров мимо ufw, не работает port-sync;
- fail2ban не установлен, не запущен или без jail для sshd;
- панели сервисов открыты наружу;
- выключены автообновления безопасности, ждут обновления, нужна перезагрузка;
- заполнен диск;
- упал сервис: xray 3X-UI, прокси MTProxyL, контейнеры AWG, WDTT, интерфейсы WireGuard.

### Клиенты и подписки

- Глобальный клиент - человек: панель сама заводит его на всех серверах во все включённые
  сервисы и следит, чтобы на серверах было ровно то, что в панели (сверка раз в 5 минут и
  кнопкой).
- Доступ клиента: все серверы и сервисы или выбор "сервер x сервис".
- VLESS (3X-UI) и MTProxy - на человека, AmneziaWG - на устройство (2.0 и 3.x), WDTT -
  пароль с числом устройств, OpenFlux - каналы клиента.
- Подписка `/sub/<токен>` для Happ, v2rayNG, Hiddify и других: ссылки со всех серверов с
  подписями "хостинг :: страна".
- Личная страница `/c/<токен>` без входа: подписка, конфиги AWG устройств с QR, ссылки
  MTProxy, WDTT, OpenFlux, расширение для браузера и приложения под ОС человека.
- Подписки и личные страницы - на отдельном имени (`SUB_DOMAIN`), токен перевыпускается
  кнопкой "Новая ссылка".
- Живая статистика в карточке клиента (только для администратора): на связи ли человек в
  каждом сервисе каждого сервера, скорость к клиенту и от клиента, трафик по счётчикам
  сервисов, график последних минут; обновляется раз в 3 с, пока карточка открыта.

### Прокси для браузера

Для компьютеров, где нельзя ставить программы: на серверах - HTTPS-прокси (Caddy с
forwardproxy NaiveProxy), у человека - расширение браузера с личной страницы:

- Chrome - через режим разработчика, ссылка клиента уже в архиве; о новой версии расширение
  сообщает само;
- Firefox - подписанное Mozilla расширение ставится в один клик, ссылку берёт с открытой
  личной страницы и обновляется само (нужен ключ API addons.mozilla.org, см.
  `apps/extension/README.md`).

В карточке клиента видно, работает ли у него расширение: браузер и версия, включён ли прокси,
выбранный сервер, ошибка в окне и когда было на связи; в списке клиентов - значок.

Выбор сервера с пингом, автовыбор, свой список адресов напрямую (домены, маски, IP, CIDR,
страницы), прямой выход для .ru, .рф и .su галочкой.

### Каталог команд

Установка, обслуживание и удаление сервисов - командами из каталога с параметрами,
проверкой перед запуском (preflight), планом и живым выводом: 3X-UI и её панель, MTProxyL,
Amnezia AWG, WDTT, OpenFlux, прокси для браузера, перевод панелей сервисов на 127.0.0.1,
уборка старых сертификатов. Каждое действие попадает в журнал; секреты в журнал не пишутся.

### Уведомления и Telegram

- Уведомления в Telegram: сервер пропал и вернулся, новые и закрытые критичные замечания
  аудита, рост банов fail2ban, обновления пакетов и сервисов, приближение оплаты хостинга.
- Бэкап панели раз в сутки файлом в Telegram (зашифрован паролем бэкапа).
- Если api.telegram.org с сервера панели недоступен, панель ходит в Telegram через
  встроенный xray и VLESS-Reality одного из своих серверов (или внешний прокси).

### Прочее

- Страница "Сервисы": все сервисы всех серверов одной таблицей.
- Страница "Приложения": свежие версии клиентских приложений с GitHub и ссылки на
  магазины по сервисам и ОС.
- Панели 3X-UI и MTProxyL на серверах слушают только 127.0.0.1 и открываются через
  поддомены панели `<сервер>-xui.<домен>` и `<сервер>-mtproxyl.<домен>` (туннель агента);
  перед входом панель проверяет агента, канал до панели сервиса и её ответ и показывает это.
- Журнал действий: кто, что, где, вывод и код выхода.
- Тёмная и светлая темы, мобильная раскладка с нижней полосой вкладок.

## Как устроено

```
   администратор                     клиенты: подписка, личная страница, расширение
        |  HTTPS                                  |  HTTPS
        v                                         v
  +--------------------------- сервер панели (docker) ---------------------------+
  |  caddy:  <домен> - панель, <SUB_DOMAIN> - /sub и /c, *.<домен> - панели      |
  |          сервисов; сертификаты Let's Encrypt, HTTP/3                         |
  |  panel:  Fastify + SQLite, интерфейс React, xray для выхода в Telegram       |
  +------------------------------------------------------------------------------+
        ^   wss://<домен>/ws/agent?v=2 - агент подключается сам
        |   (X25519 + подпись ключом панели ed25519, затем AES-256-GCM)
  +-----+-----------+   +-----------------+   +-----------------+
  |  vps-agent      |   |  vps-agent      |   |  vps-agent      |
  |  3X-UI, MTProxyL|   |  AWG, WDTT, ... |   |  ...            |
  +-----------------+   +-----------------+   +-----------------+
```

- **Панель** (`apps/server`, `apps/web`): Fastify 5, better-sqlite3 с Drizzle, React 19,
  Vite, Tailwind 4, TanStack Router и Query. Живые обновления интерфейса - по `/ws/ui`.
- **Протокол** (`packages/protocol`): zod-схемы сообщений агент-панель и типы API, общие для
  сервера и интерфейса; Go-зеркало - в `apps/agent/internal/proto`.
- **Агент** (`apps/agent`): один статический бинарник на Go (linux amd64 и arm64) и
  systemd-юнит. Снимок сервера раз в 5 минут и сразу при падении или подъёме сервиса,
  метрики, операции из белого списка, терминал, туннель к панелям сервисов на 127.0.0.1,
  самообновление с проверкой контрольной суммы.
- **Расширение** (`apps/extension`): чистый JS без сборки, один код для Chrome (MV3, архив с
  личной страницы) и Firefox (MV2, подписанный архив, автообновление).

## Требования

**Сервер панели**

- Linux с docker и compose plugin (проверено на Ubuntu 24.04; docker скрипт установки
  поставит сам).
- Домен с A-записями на сервер панели: имя панели, имя подписок (`SUB_DOMAIN`, по желанию)
  и `*.<домен>` для панелей сервисов.
- Открытые 80/tcp, 443/tcp и 443/udp.

**Управляемые серверы**

- Linux x86_64 или arm64 с systemd; root.
- Доступ к панели по HTTPS исходящим соединением. Входящий SSH нужен только для установки
  агента из панели; можно и без него - выполнить команду установки вручную.

## Установка панели

На сервере панели (root), после A-записей домена панели и имени подписок на этот сервер:

```bash
git clone https://github.com/iKonan-ru/vps-panel.git /opt/vps-panel
/opt/vps-panel/deploy/install.sh
```

Скрипт спросит домен панели, имя подписок и почту для Let's Encrypt, проверит DNS и порты,
поставит недостающее (docker, fail2ban), запишет `deploy/.env` с новым `SESSION_SECRET`,
соберёт агента и файлы сервисов (Go скачает во временную папку, если его нет), запустит
контейнеры и дождётся ответа панели. Сертификаты Caddy получит сам. Без вопросов:
`PANEL_DOMAIN=... ACME_EMAIL=... SUB_DOMAIN=... deploy/install.sh -y`.

Сразу после установки откройте панель и пройдите мастер первой настройки
(администратор, пароль, 2FA): до этого он открыт любому, кто первым зайдёт на адрес.

<details>
<summary>Установка вручную</summary>

```bash
git clone https://github.com/iKonan-ru/vps-panel.git /opt/vps-panel
cd /opt/vps-panel/apps/agent && make build-all        # бинарники агента в dist/ (нужен Go)
mkdir -p /opt/vps-panel/deploy/agent-dist
cp /opt/vps-panel/dist/* /opt/vps-panel/deploy/agent-dist/ && chmod -R a+rX /opt/vps-panel/deploy/agent-dist
sh /opt/vps-panel/tools/build-wdtt.sh && sh /opt/vps-panel/tools/build-naive.sh   # файлы WDTT и naive

cd /opt/vps-panel/deploy
cp .env.example .env              # заполнить, см. ниже
mkdir -p data && chown 1000:1000 data
docker compose up -d --build
```

fail2ban для входа в панель, тестовый режим без HTTPS и тонкости - в `deploy/README.md`.

</details>

## Настройки окружения

Файл `deploy/.env`:

| Переменная | Обязательна | Что это |
| --- | --- | --- |
| `PANEL_DOMAIN` | да | домен панели (A-запись на этот сервер) |
| `ACME_EMAIL` | да | почта для Let's Encrypt |
| `SESSION_SECRET` | да | секрет сессий и ключ шифрования данных в базе: `openssl rand -base64 48`; потерять - значит потерять зашифрованное |
| `SUB_DOMAIN` | нет | отдельное имя для подписок и личных страниц, например `sub.example.com`; пусто - они на имени панели |
| `TG_PROXY_URL` | нет | внешний HTTP-прокси до api.telegram.org, если встроенный xray не настроен |
| `LOG_LEVEL` | нет | `info` по умолчанию |

Остальное (Telegram, уведомления, бэкап, выход в Telegram, хеши звонков WDTT, документы
OpenFlux) настраивается в интерфейсе, раздел "Настройки".

## Подключение сервера

1. "Серверы" - "Добавить сервер": имя, адрес, порт SSH, хостинг и оплата (по желанию).
2. Установка агента: панель заходит по SSH (пароль root или ключ панели) и ставит агента
   сама или показывает команду для ручного запуска на сервере.
3. Агент регистрируется одноразовым токеном, запоминает ключ панели и с этого момента
   работает только с ней.
4. Во вкладке "Обзор" - замечания аудита с кнопками исправления; сервисы ставятся из
   каталога команд.

Отпечаток ключа хоста SSH панель запоминает при первом подключении и сверяет потом;
после переустановки ОС сервера его сбрасывают в окне установки агента.

## Обновление

- **Панель**: снова `deploy/install.sh` на сервере панели (git pull, сборка, пересборка
  контейнеров; `.env` и данные не трогаются). Пока идёт сборка, работает прежняя версия.
  С машины разработки - `tools/ship.sh` (проверки, коммит, выкладка через `deploy/push.sh`;
  сервер и домен - в `.ship.env`, см. шапку `tools/ship.sh`).
- **Агенты**: версия агента - `apps/agent/VERSION` плюс хеш исходников. Новые бинарники в
  `deploy/agent-dist` - и панель покажет "есть обновление"; обновить - кнопкой в карточке
  сервера или всех по очереди на странице серверов.
- **Сервисы**: обновления 3X-UI и MTProxyL панель проверяет раз в 6 часов, обновления
  пакетов приходят в снимках агента; всё это видно в карточке, на странице серверов и в
  Telegram.

## Бэкап и восстановление

Раздел "Настройки" - "Бэкап панели": пароль бэкапа (храните отдельно), отправка в
Telegram раз в сутки, кнопки "Отправить сейчас" и "Скачать". В архиве - снимок базы,
`SESSION_SECRET`, ключ SSH панели, ключ панели для агентов и конфиг xray.

Восстановление (на новом сервере - после установки панели по шагам выше):

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -iter 100000 -in vps-panel-backup-<дата>.tar.gz.enc | tar xz
cd /opt/vps-panel/deploy && docker compose stop panel
cp vps-panel-backup/panel.db vps-panel-backup/panel_ssh_ed25519* vps-panel-backup/panel_agent_ed25519.pem data/
chmod 600 data/panel_ssh_ed25519 data/panel_agent_ed25519.pem
mkdir -p data/xray && cp vps-panel-backup/xray/config.json data/xray/
rm -f data/panel.db-wal data/panel.db-shm && chown -R 1000:1000 data
# SESSION_SECRET из vps-panel-backup/panel.env - в .env
docker compose up -d panel
```

Без ключа панели для агентов (`panel_agent_ed25519.pem`) восстановленной панели не
поверит ни один агент.

## Безопасность

- Вход: пароль (argon2) и TOTP, резервные коды, пауза после неудачных попыток, fail2ban по
  логу Caddy; cookie сессии с префиксом `__Host-`.
- Канал агента: агент верит ключу панели ed25519, а не домену и сертификату; токен агента
  по сети не передаётся (доказательство HMAC по стенограмме рукопожатия), сообщения
  шифруются AES-256-GCM.
- Агент выполняет только операции из белого списка с проверкой аргументов, команды
  собираются без оболочки.
- Пароли панелей, ключи клиентов AWG и токены 3X-UI в базе зашифрованы AES-256-GCM ключом
  из `SESSION_SECRET`.
- Секреты не пишутся в журнал действий, в значения по умолчанию команд и в вывод.
- Контейнеры урезаны: корень только для чтения, `cap_drop: ALL`, `no-new-privileges`;
  CSP, панель закрыта от поисковиков.
- Панели сервисов на серверах слушают только 127.0.0.1, вход в них - через панель.
- Изменения на серверах - только явными действиями с подтверждением, по одному серверу.

## Разработка

Нужны Node.js 22+, pnpm (через corepack) и Go 1.25 для агента.

```bash
corepack pnpm install
corepack pnpm dev                                   # сервер и интерфейс в режиме разработки
corepack pnpm --filter @vps/protocol build          # после правок протокола
corepack pnpm -r --filter @vps/protocol --filter @vps/server --filter @vps/web exec tsc --noEmit
npx biome check --write apps/web/src apps/server/src apps/server/test packages/protocol/src
cd apps/server && npx vitest run
cd apps/agent && go vet ./... && go test ./... && make build-all
```

Перед выкладкой - `tools/check.sh`: протокол, типы, biome, тесты сервера, агент (gofmt,
vet, test, govulncheck), `pnpm audit`, только клавиатурные символы в файлах.

Правила проекта: код, комментарии, интерфейс и документы - на русском; в файлах только
символы с клавиатуры (дефис вместо тире, прямые кавычки).

## Структура репозитория

```
apps/
  server/       панель: Fastify, база, маршруты API, каталог команд, сверка клиентов
  web/          интерфейс: React, свой UI-кит в components/ui
  agent/        агент на Go: cmd/vps-agent, internal/* (снимок, аудит, сервисы, терминал...)
  extension/    расширение Chrome и Firefox для прокси для браузера
packages/
  protocol/     zod-схемы протокола агент-панель и общие типы
deploy/         install.sh, Dockerfile, docker-compose, Caddyfile, fail2ban, скрипты выкладки
tools/          check.sh, ship.sh, сборка wdtt-server и Caddy с forwardproxy, подпись расширения Firefox
```

## Документация

| Документ | О чём |
| --- | --- |
| `deploy/README.md` | сервер панели: установка, Caddy, fail2ban, выход в Telegram, бэкап, выкладка |
| `apps/agent/README.md` | агент: установка, конфиг, флаги, канал, операции, сборка, отладка |
| `apps/extension/README.md` | расширение Chrome и Firefox: файлы, установка, подпись, обновление |
